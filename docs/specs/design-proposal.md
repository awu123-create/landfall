## 1. 产品定位与课程需求映射

系统定位为**仿小红书网页版的多媒体内容社区「见屿」**（纯 Web 形态），搭配一套**独立的管理员运营审核后台**：

- **用户端（`@landfall/web-user`）**：Vue 3 响应式网页应用。宽屏展示左侧导航、多列瀑布流与作品详情弹窗/独立页；窄屏自动切换为移动端双列瀑布流与底部导航。
- **管理后台（`@landfall/web-admin`）**：独立 Vue 3 管理后台，覆盖用户管理、角色权限树配置、作品管理、评论管理、标签管理、敏感词库维护、待复审队列及活跃统计看板。
- **单一模块化单体后端（`com.landfall`）**：双前端共用同一套 Spring Boot 3 服务、同一套 PostgreSQL 16 数据库与同一套 Redis 7 会话权限体系。日常开发每人本机运行 Docker（PG + Redis + 本地磁盘存储），全链路离线可演示；云端部署通过 Spring Profile 切换云端数据库与同机 MinIO/S3。

## 3. 跨模块核心业务不变量与状态契约

### 3.1 作品可见性与治理状态解耦

- **`visibility`（作者意愿）**：`PUBLIC`（所有人与游客可见）、`FRIENDS`（仅作者及互关好友可见）、`PRIVATE`（仅作者本人可见）。
- **`status`（平台状态）**：`PUBLISHED`（正常展示）、`TAKEDOWN`（违规下架，仅作者本人与管理员可见）、`DELETED`（逻辑删除）。
- **硬约束**：AI 审核拦截或管理员下架**只允许将 `status` 置为 `TAKEDOWN`，严禁覆盖 `visibility`**，确保人工复审恢复公开后仍沿用作者原定可见范围。

### 3.2 检索、评论、评分与互关好友

- **检索与排序**：关键词采用 PostgreSQL `ILIKE`（规避 `pg_trgm` 对 1~2 字中文词失效问题）；日期区间统一按 `Asia/Shanghai` 折算为左闭右开 `[startDate 00:00:00, endDate + 1d 00:00:00)`；支持 `RECOMMEND`、`LATEST`、`HOT`、`TOP_RATED`（默认要求评分人数 `rating_count >= 3`，全站无满足门槛作品时降级放宽）。标签归一化后与昵称、简介一样须同步过 DFA 检测。
- **两级平铺评论**：一级评论 `root_id = NULL`、`parent_id = NULL`（严禁使用哨兵值 `0` 破坏自关联外键）；子回复统一挂在对应一级评论 `root_id` 下并记录 `parent_id` 与 `reply_to_user_id`；评论点赞用独立唯一约束表维护。
- **1~5 星评分**：每名用户对同一作品限评 1 次（再次提交更新原分），作者不可自评（`40001`）；事务内同步维护总分、人数与均分。
- **互关即好友**：关注表仅存单向 `(follower_id, followee_id)`，**不设 `is_mutual` 冗余列**（防并发互关漏标），依托双向联合索引通过 SQL `EXISTS` 实时判定。

### 3.3 会话、双层权限与软删除级联

- **不透明 Token 与公开页静默降级**：Redis 维护 Token 详情与用户在线 Token 集合；修改密码、重置密码、封禁、软删账号时清空集合实现全端下线。Spring Security 逐条显式列出公开只读白名单（禁止按 HTTP `GET` 粗暴放行）：命中公开接口时，有效 Token 注入用户上下文，**过期或已失效的残留 Token 静默忽略并按游客放行**，绝不在公开页弹 `401`。需登录接口区分未带 Token（`401` / `20001`）与失效 Token（`401` / `20006`）。
- **功能级 RBAC 与后台准入**：5 表树形权限模型预置 `ROLE_USER`、`ROLE_MODERATOR`、`ROLE_ADMIN`（内置角色防删 `70001`）；后台登录与全部 `/api/v1/admin/**` 强制校验 `admin:access`（无权限返 `403` / `20007`）；角色或权限树变更时同步清除关联用户的 Redis 权限缓存。
- **数据级策略（`PostAccessPolicy` / `CommentAccessPolicy`）**：所有业务模块统一调用策略类，禁止散落手写越权判断。**6 类必检 `canView` 入口**：① 作品详情；② 评论与子回复列表；③ 点赞/收藏/评分/发评写接口；④ 我的收藏列表（对事后转私密或下架作品做过滤或占位提示）；⑤ 发现流/关注流/搜索/个人主页列表（SQL 与 `canView` 同口径）；⑥ 详情页 AI 总结生成与读取。
- **用户软删除**：写入 `deleted_at` 并踢下线，同步将其作品与评论置为 `DELETED`、异步回算受影响作品互动计数与均分；用户名与邮箱采用部分唯一索引（`WHERE deleted_at IS NULL`）支持重注册。

### 3.4 人机协同审核状态机与「阿瓦隆」评论治理

- **同步 DFA 分级处置**：作品标题/正文、标签、昵称、简介命中高危（`HIGH`）或一般（`NORMAL`）敏感词均直接拦截（`400` / `30004`）。评论命中 `HIGH` 直接拦截；命中 `NORMAL` 正常返回 `200`，落库标为 **`SHADOW_HIDDEN` + `MANUAL_REVIEW`** 且暂不计入公开评论数——查询时**仅发评人本人与管理员可见，其他用户与游客不可见**，待后台人工放行后转为 `NORMAL` 并补增计数。
- **6 态 `audit_status` 流转**（作品与评论共用 `PENDING_AI` / `AI_PASSED` / `MANUAL_REVIEW` / `AI_REJECTED` / `MANUAL_PASSED` / `MANUAL_REJECTED`）：

| 触发事件 | 新 `status`（作品 / 评论） | 新 `audit_status` | 关键约束 |
| :--- | :--- | :--- | :--- |
| 新发内容未命中 DFA / 编辑已公开作品 | `PUBLISHED` / `NORMAL` | `PENDING_AI` | 先发后审（编辑公开帖必须重审），异步投递 AI 复查 |
| 新发评论命中 `NORMAL` 敏感词 | `SHADOW_HIDDEN`（仅评论） | `MANUAL_REVIEW` | 仅发评人与管理员可见，进后台待复审队列 |
| 作者修改已下架作品（`TAKEDOWN`） | 保持 `TAKEDOWN` | `MANUAL_REVIEW` | 禁止改一字自动恢复公开，须经人工复审 |
| AI 复查 `PASS` / `REVIEW` / 超时异常 | 保持当前 `status` | `AI_PASSED` 或 `MANUAL_REVIEW` | 异常或超时自动转人工兜底，配合定时补偿重试防永久卡在 `PENDING_AI` |
| AI 复查 `REJECT` | `TAKEDOWN` | `AI_REJECTED` | 保留原 `visibility`；评论同步扣减公开计数 |
| 管理员复审通过 / 驳回（或主动下架） | `PUBLISHED`/`NORMAL` 或 `TAKEDOWN` | `MANUAL_PASSED` / `MANUAL_REJECTED` | 恢复或下架均保留作者原 `visibility`，同步修正公开评论数 |

- **双配额隔离**：异步合规审核使用独立系统配额；用户主动触发的发布页助手与详情页总结走个人每日限额（超限返 `429` / `60001`，上游不可用返 `503` / `60002`）。

### 3.5 媒体先传后绑、转码降级与错误码号段

- **先传后绑**：媒体上传先记 `uploader_id` 与 `UNBOUND` 返回素材 ID；发帖事务内校验归属与未绑定状态（或已绑当前编辑作品）后置 `BOUND`；定时清理超时 24 小时的孤儿文件与记录。
- **阈值与流式降级**：图片/视频大小与时长上限由环境变量驱动并通过公开配置接口下发前端预检，同时解除 Spring 默认 1MB 上传限制。图片同步生成瀑布流缩略图；本机或容器装有 FFmpeg 时异步抽帧并切片 HLS（含超时补偿重试），否则自动标为 HTTP `Range`（`206`）模式播放。媒体对象路径采用随机 UUID，业务接口由 `PostAccessPolicy` 控权下发 URL，静态流读取层不验 `Authorization` 头以兼容原生 `<video>` 与 `.ts` 分片。
- **统一错误码号段**：成功固定 `code = 0`；错误码按工作包分号段登记在公共枚举——`1xxxx` 通用参数/限流/系统异常、`2xxxx` 认证会话与 RBAC、`3xxxx` 作品/媒体/敏感词拦截、`4xxxx` 评论与评分、`5xxxx` 社交关注、`6xxxx` AI 限流与降级、`7xxxx` 后台角色与词库治理。

### 4.3 并行协作 5 条防冲突硬规则

1. **页面壳 + 独立组件插槽隔离**：禁止多人混改同一 `.vue` 大文件。详情页壳归包 3（包 2/4/5/7 各自维护独立组件挂载），个人主页壳归包 5（复用包 3/4 列表组件），管理后台布局壳归包 6（包 7 独立维护看板、复审队列与敏感词三页）。
2. **Flyway 迁移只增不改、日常开发隔离共享库**：日常开发默认连本机 Docker；表结构变更一律新增时间戳迁移脚本，**严禁修改任何已合入 `dev` 的历史 SQL 脚本**。
3. **契约生成物不入库**：后端变更接口须同步维护 OpenAPI 注解，前端本地与 CI 构建期生成 `@landfall/shared` 客户端，消除生成代码合并冲突；改动公共底座或共享拦截器须经跨包评审。
4. **分支规范与密钥隔离**：开发分支统一从 `origin/dev` 按 `<type>/<id>-<slug>` 切出并通过 Squash merge 合入 `dev`（详见 [docs/agents/github.md](../agents/github.md)）；API Key、云端数据库密码与上传物理路径统一走环境变量与 `.env`，严禁入库。
5. **外部依赖可降级**：无 FFmpeg 自动走 HTTP `Range` 播放，无大模型密钥或超时自动提示降级并将待审内容转 `MANUAL_REVIEW`，保障核心社区功能离线可跑通。
